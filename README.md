# Pulsar Kernel

Pulsar is a custom Linux 4.14 kernel source for the Xiaomi Redmi Note 9 (**merlin**) based on the MediaTek **MT6768** platform.

## Project identity

- Kernel name: **Pulsar**
- Local version: **Pulsar**
- Architecture: **ARM64**
- Target: **Xiaomi Redmi Note 9 (merlin)**
- SoC: **MediaTek MT6768**
- Kernel base: **Linux 4.14.328**

The merlin defconfig enables automatic SCM version suffixes with `CONFIG_LOCALVERSION_AUTO=y`. The resulting release string therefore includes the Pulsar local version followed by the Git revision information generated by the kernel build system.

## Repositories

- **Kernel source:** [android_kernel_xiaomi_mt6768-s](https://github.com/a03corerooted-dev-ctrl/android_kernel_xiaomi_mt6768-s/tree/kernel-tree-6)
- **Build system:** [NonGKI_Kernel_Built_Action](https://github.com/a03corerooted-dev-ctrl/NonGKI_Kernel_Built_Action/tree/s-shockwave-kernel)
- **AnyKernel3 installer:** [AnyKernel3](https://github.com/a03corerooted-dev-ctrl/AnyKernel3/tree/proton)

The build workflow is configured to fetch the kernel source from the `kernel-tree-6` branch and the installer from the `proton` branch. Keep these branch references aligned when changing the build pipeline.

## Building

The supported automated build path is the linked GitHub Actions build system. Its `config-xxksu.env` and `config-ksun.env` files define the source repository, source branch, ARM64 architecture, `Image.gz-dtb` output and AnyKernel3 repository/branch.

For a manual build, use an ARM64 Android kernel toolchain and the merlin defconfig:

```sh
export ARCH=arm64
make O=out merlin_defconfig
make -j"$(nproc)" O=out
```

The exact compiler and additional build variables must match the selected toolchain and the configuration used by the automated builder.

## Versioning

The merlin defconfig contains:

```text
CONFIG_LOCALVERSION="-Pulsar"
CONFIG_LOCALVERSION_AUTO=y
```

The `-Pulsar` suffix is the configured local name. With automatic local versioning enabled, the kernel build system appends SCM information (for example, the commit distance/hash and a dirty marker when applicable). Do not disable this option if reproducible source-state identification is required.

## Scope

Pulsar branding changes do not imply changes to scheduler, CPU frequency, memory management, storage encryption, or device drivers. Functional changes should be developed and tested separately against the MT6768 device.
